All printable checklists

Magento 2 to Shopify

Copy this file into your tracker and tick items per phase. Each line is one check. "Why it bites" is the failure that shows up after launch if you skip it. These are the Magento 2 / Adobe Commerce checks, written so this file can be used on its own. The WooCommerce list is CHECKLIST.md.

Practise on test-catalogs/magento-basic. magento.csv is a fictional Magento 2 product export. shopify.csv is that catalog in the Shopify product CSV. The mapping used in the pair is in test-catalogs/README.md.

Before you start

  • Freeze product edits, then export the catalog you will actually import: Admin, System > Data Transfer > Export, entity type Products, file format CSV. Why it bites: a product changed after that export is absent from every later comparison. Export data
  • Export tier prices and customer-group prices as a second file, entity type Advanced Pricing. Why it bites: Adobe's attributes reference lists those columns in a separate Advanced pricing section, not in its table of a typical product export. Check in your own export whether the product file also carries them. Export data Product data attributes
  • Export stock sources on their own, entity type Stock Sources. Why it bites: that file is a separate entity type from Products. Check in your own export before you treat product qty as the only quantity. Export data
  • Turn on Fields Enclosure when a cell holds special characters, and edit the file in a UTF-8 editor. Why it bites: configurable_variations is a pipe-separated list of variations, each a comma-separated list of code=value pairs. The export page lists the equal sign, the greater-than and less-than symbols, single and double quotes, the backslash, the pipe, and the ampersand as characters that can cause problems during data transfer, and says the Fields Enclosure checkbox marks them as an escape sequence. It does not name the comma, and Excel can insert characters into the header that Commerce cannot read back. Export data CSV files
  • Open the file with commas between values, and double quotes around multiple values. Why it bites: the CSV page says values are separated by commas, and that multiple values are enclosed in double-quotes. A comma is the default separator. CSV files
  • Read the header row against a typical product export, then against your file. Why it bites: the attributes reference lists those columns in the default order, from an installation with sample data, two websites, and several store views. sku is the only required value. Custom attributes add columns. Product data attributes
  • Check an excluded attribute in your own export before you treat a missing header as a missing product. Why it bites: the export page describes an excluded attribute two ways: the column stays in the file but empty, and, in its filter table, the column is left out. Check in your own export which you got. The order of the columns after sku does not matter on import, and sku should be first. Export data Product data attributes

Product data

Note on variation cells: the configurable import example writes each variation as sku and attribute codes separated by commas, with a pipe between variations (sku=…,size=…,color=…|sku=…). The attributes reference's example also puts price, display, and image in that cell, and it lists _super_products_sku, _super_attribute_code, _super_attribute_option, and _super_attribute_price_corr. Check in your own export which cells are filled. Import configurable products Product data attributes

Note on tier-price columns: the tier-price import page lists sku, tier_price_website, tier_price_customer_group, tier_price_qty, tier_price, and tier_price_value_type. The attributes reference also lists tier_price_customer, group_price_website, and group_price_customer_group, and it does not list tier_price_value_type. Check in your own export. Import tier prices Product data attributes

Note on category separators: the attributes reference separates category paths with a pipe. The CSV structure page says the comma is the default multiple-value separator, and that you can change it. Check in your own export. Product data attributes CSV files

  • Map each simple variation to one Shopify variant under the configurable product's handle. Leave the configurable row out of the variant list. Why it bites: the product export has one row for the configurable product and one row for each simple variation. Each variation is a separate simple product with its own SKU. Import configurable products
  • Use the variation's price, not the price typed on the configurable row. Why it bites: a configurable product does not have its own price in the catalog. The price customers see comes from its in-stock child products, and the price typed on the configurable product is overridden by those children. Configurable product
  • Read variation values from configurable_variations on the configurable row. Why it bites: the attribute in that cell is the attribute code, not the storefront label. configurable_variation_labels is documented with the examples Choose Color: and Choose Size:. The two example shapes are in the note above. Import configurable products Product data attributes
  • Keep variation attributes to three Shopify options. Why it bites: a Shopify product can have up to three options, so a fourth Magento variation attribute has no option column in the product CSV. Shopify's page on adding variants points to a third-party app, or to theme code that reads line item properties, for more than three options. Adding variants
  • Stay within 2,048 variants on one product. Why it bites: you can create up to 2,048 variants per product, and some themes and apps might not support more than 100. A store with 500,000 or more variants can add up to 10,000 new variants in a day by CSV, unless it is on the Plus plan. Adding variants
  • Confirm each variation attribute is global scope and required. Why it bites: Adobe says variation attributes must have a global scope and customers must be required to choose a value. The configurable product page's attribute table lists Dropdown, Visual Swatch, or Text Swatch, its key considerations also name multiple select, and the configurable import page lists Dropdown, Visual Swatch, Text Swatch, and Multi-Select. Configurable product Import configurable products

Why it bites: the product CSV guide says the Option1 name should be Default Title when the product has only one option. The inventory CSV guide says the option name is Title and the option value is Default Title. Those two pages disagree. Product CSV columns Inventory CSV

Why it bites: the help page's column table, the sample file that page links, and older names such as Variant SKU and Body (HTML) are not one list. The table says Barcodes and Option1 LinkedTo. The sample template says Variant Barcodes and Option1 Linked To. Product CSV columns Sample product template Common import problems
  • Put special_price in Shopify Price, and price in Compare-at price, only when that special price is the amount the customer pays. Why it bites: special_price is the discounted price during special_price_from_date and special_price_to_date. A Shopify sale displays only when compare-at is higher than price. The product CSV has no start-date or end-date column, so a price you copy stays in force after the Magento end date. Special prices Sale prices Product CSV columns
  • Read the special-price dates before you copy the price. Why it bites: on Magento Open Source, the simple start and end dates take effect at 00:01 on the start date and run until 23:59 on the day before the end date. Adobe Commerce scheduled updates can also set an hour and minute. Check in your own export whether the date cells include a time. Special prices
  • Compare the storefront price with special_price before you trust the CSV. Why it bites: the final price is the minimum of the regular price, the group or tier price, the special price, and a catalog price rule, plus the minimum price of each required custom option. Catalog price rules are not columns in the product attributes reference. Special prices Product data attributes

  • Keep tier and group prices out of Shopify Price. Why it bites: the product CSV has one Price and one Compare-at price per variant, with no quantity break and no customer group.   • Pick the store view whose name and price you are launching. Why it bites: a blank store_view_code means the default store view.   • Check in your own export whether a store-view row repeats the SKU before you count rows as products.   • Treat ACSD-59378 and ACSD-48210 as bug reports, not as the export format. Why it bites: ACSD-59378 is written for 2.4.5-p5 and ACSD-48210 for 2.4.4-p2 (compatible with 2.4.4 to 2.4.6-p7), and Adobe says both were fixed in 2.4.7.   • Read product_websites as the list of website codes. Why it bites: multiple codes are separated by a comma and no space, for example base or base,website2. When website_id is blank, the product is available in all websites. Product data attributes
  • Decide which website and store view is the Shopify store. Why it bites: websites, stores, and store views are a hierarchy, and each store view can have its own base URL. The store view is where translation and the currency symbol are set. Websites, stores, and views
  • Map Published on online store only to the online store channel. Why it bites: that column is the online store sales channel. The product CSV cannot bulk-update availability on other sales channels. Shopify's product CSV has no store-view column and no website column. Product CSV columns
  • Copy url_key into the Shopify URL handle without the suffix and without a category path. Why it bites: the URL key is the part of the URL that identifies the product, in lowercase with hyphens, and the suffix and category path come from configuration. A valid URL handle can contain letters, dashes, and numbers, but it can't contain any spaces. A period or slash is not on that list, so an old .html suffix or category path belongs in a redirect (see SEO), not in the handle. URL key Catalog URLs Product CSV columns
  • Give each product its own handle. Why it bites: the handle is the unique identifier for each product and is what appears in the product URL. Product CSV columns
  • Put each image on a public https URL. Why it bites: an export stores a relative path, such as /sample_data/m/b/mb01-blue-0.jpg, not a URL a browser can fetch. Shopify downloads Product image URL during import, and image URLs from external sources need to be publicly accessible. Product data attributes Product CSV columns
  • Give each image role its own look before you collapse files. Why it bites: the base image is the main image on the product detail page, the small image is used in listings on category and search results pages, and thumbnail images appear in the thumbnail gallery, shopping cart, and some blocks. A swatch can be used to illustrate the color, pattern, or texture. By default, all roles are assigned to the first image that is uploaded. Product images
  • List each distinct file once, one Shopify row per image. Why it bites: by default Adobe assigns all roles to the first image that is uploaded, and that is still one image. The image import page says several images for one SKU go in additional_images, separated by commas. Check in your own export whether you have one path, a comma-separated list, or extra rows.   • Map product_online separately from visibility. Why it bites: product_online 1 means the product is enabled and available for sale, and 2 means it is disabled and not available for sale. visibility is Not Visible Individually, Catalog, Search, or Catalog, Search. Product data attributes

Customers and orders

  • Import products first, then customers, then historical orders. Why it bites: orders need products and customers already in the store if those records are to connect. Migrate to Shopify
  • Export customers from their own entity types, Customers Main File and Customer Addresses. Why it bites: those are separate entity types on the export screen. Check in your own export before you look for customer rows on the product file. Export data
  • Import customer profiles with the customer CSV, and plan for the 15 MB file limit. Why it bites: the Email column has to be present, total spent and total orders are not imported, and duplicate emails or phone numbers are skipped except the last one. Importing customers
  • Do not expect passwords to come across. Why it bites: the customer CSV cannot migrate passwords, and the import guide says to invite customers to create new passwords. If the store uses customer accounts with sign-in links, customers instead enter their email and a one-time 6-digit code, and a password is not required. Check which account type the destination store uses. Importing customers Customer accounts
  • Move order history with an app or the Order API, not with the product or customer CSV. Why it bites: orders are not one of the export entity types on the data-transfer screen. The customer CSV cannot import orders. Shopify's migration guide lists historical orders under migration apps, the Order API, and the Transaction API. Export data Migrate to Shopify Importing customers
  • Turn off new-order mail before you import historical orders. Why it bites: people set to receive that mail will get one email per imported historical order unless those notifications are off during the import. Migrate to Shopify

SEO

  • Read the old product path from the live page before you write a redirect. Why it bites: url_key is not the whole path. Add the configured suffix (html, htm, or none) and add the category path only when the store includes it. The default is to leave the category path out. Catalog URLs URL key Catalog configuration
  • Copy the request path from the live page, and keep it unique for that store view. Why it bites: a product URL rewrite can be saved with or without the category path, and the request path has to be unique per store view. Product URL rewrites
  • Recreate Commerce redirects in Shopify. Why it bites: a Commerce redirect stays in Commerce. With save_rewrites_history set to 1 and a new url_key, import creates a 301 there. The export screen's entity types do not include URL rewrites, so those rows are not in the product CSV. Product data attributes Export data
  • Keep a permanent redirect in Commerce only if you still need it there. Why it bites: the store can create a permanent redirect when the URL key changes. You can also add a 301 or a 302 under Marketing > SEO & Search > URL Rewrites. During a product rewrite, GET parameters on the URL are removed. Automatic redirects Product URL rewrites
  • Add a Shopify redirect for every old product and category path you still need. Why it bites: a redirect works only when the old path 404s. You cannot redirect reserved paths such as /products, /collections, or /collections/all. A store can store 100,000 URL redirects, or 20,000,000 on the Plus plan. URL redirects
  • Do not redirect a .html URL to the same path with .html removed. Why it bites: URLs ending in .html cannot be redirected to the same URL without .html. Shopify treats these as the same URL. Query strings might not redirect as you expect. URL redirects
  • Read the new path from the live Shopify page before you write the redirect. Why it bites: the handle is the unique identifier for each product and is what appears in the product URL. Product CSV columns
  • After you remove a redirect, request the old URL again. Why it bites: a 301 is cached by browsers and search engines, so a redirect you remove can keep working in people's browsers until the cache expires. URL redirects
  • Fill Shopify SEO title and SEO description from meta_title and meta_description where the old listing mattered. Why it bites: Commerce asks for a meta title of fewer than 70 characters, and a meta description of 150 to 160 characters, in a field that accepts up to 255. The product CSV allows an SEO title of up to 70 characters and an SEO description of up to 320. Left blank, Shopify uses the product title and description.   • Spot-check a configurable product, one variation that was on special, one product that was disabled (product_online 2), and one name that existed only on another store view.

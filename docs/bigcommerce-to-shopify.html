BigCommerce to Shopify

Copy this file into your tracker and tick items per phase. Each line is one check. "Why it bites" is the failure that shows up after launch if you skip it. These are the BigCommerce checks, written so this file can be used on its own. The WooCommerce list is CHECKLIST.md.

Practise on test-catalogs/bigcommerce-basic. bigcommerce.csv is a fictional legacy Bulk Edit export. shopify.csv is that catalog in the Shopify product CSV. The mapping used in the pair is in test-catalogs/README.md.

Before you start

  • Freeze product edits, then export from the experience the store still has. Why it bites: the legacy tool can only be used in a store with a single native storefront. The modern tool can be used in a single-storefront store and in a Multi-Storefront store, and "it is a prerequisite for enabling Multi-Storefront." "You cannot revert back to the legacy Import/Export experience after enabling Multi-Storefront," though a banner before that step "provides the option to Rollback to the previous version." Legacy overview
  • On the legacy experience, choose Bulk Edit when you want the majority of fields, or Default when you only need the basics. Why it bites: Bulk Edit "was made for updating your product information" and "includes the majority of exportable fields and has specifically named columns that let you skip steps in the importing process." Default "includes only basic product details such as name, weight, description, and price." Custom templates are created at Settings › Export templates, and BigCommerce recommends a copy of Bulk Edit for editing products in bulk. Legacy export
  • On the modern experience, take the default product CSV. Why it bites: "All exportable fields are included in the default product CSV file; custom export templates are not supported," and the modern overview says the same without naming a Bulk Edit template. The sale-pricing page recommends a custom export template for "a large number of products without options" or regular sale-price changes. It does not say which tool, and only the legacy tool has custom templates, so check which tool your store has. Modern export Modern overview Sale pricing
  • On a legacy export, copy Bulk Edit at Settings › Export templates, check Include Product Options in the copy, then export. Why it bites: "If you want variant options and modifier rules to be present under products in your CSV file, check the box next to Include Product Options." That box is a custom export template setting, and BigCommerce does not say whether the built-in Bulk Edit template includes options. "The legacy Import/Export tool uses Y or N Boolean values," and Boolean Format can change them, so check that SKU and Rule rows are in the file. Legacy export

Product data

Note on the two row shapes: a legacy SKU row "includes variant identifiers, stock levels, and dimensions," and a Rule row "defines the price, weight, and image that appears when the variant is selected on the storefront." The modern column says "All variant information is present in a single Variant row." The transfer page, on a custom export template, says that apart from the variant image URL, "all information in Rule rows are also present in the SKU rows," which is not the legacy table's split. Check in your own export which cells are filled on which row. Legacy overview Legacy to modern transfer

Note on option text: the complex-attributes, first-import, and updating pages all write two options on one variant as [RB]Size=Small,[CS]Color=Blue:#0000FF, with no space before or after the comma. Check in your own export. Complex attributes Importing your first product Updating products

Note on sale price and retail price: sale price and MSRP "cannot be assigned to variants via import," but the modern column says "Adding and updating Retail (MSRP) Price and Sale Price is supported on variants." The legacy tool updates Sale Price "for products without options or variants." The FAQ, answering a question about the legacy (v2) product experience, says "Product option price rules that are Fixed are not affected by Sale Price." Legacy fields Legacy overview Sale pricing

Note on a blank price: a new product says "If left blank, the product will have a price of 0." A new modern variant says "Leave the Price field blank if you want the variant to have the same price as the base product." The transfer template says "If a variant’s price or weight is the same as the base product, those fields will be blank in the Variant row." That describes the template, not a Bulk Edit file. Note on names that do not match: the fields page says "This field is called Product Image File - 1 in the Bulk Edit template" for Product Image Path - 1, yet its Manually Entered Fields table also lists Product Image File - 1 as the WebDAV location of the image. The digital file there is Product File Path- 1, with no space before the hyphen, while the complex-attributes page names Product File Path - 2. Modern images ask for Item, ID, and Image URL (Import), and a later table says Item Type and Product ID. Legacy fields Complex attributes Modern complex attributes

  • Read Item Type before you count rows as products. Why it bites: "Type in Product for products, SKU for variants, and Rule for variant or modifier rules." On the modern file the column is Item, and "adding “variant” will cause import errors" if the casing is wrong. The transfer template renames Item Type to Item, Product ID to ID, and Product Name to Name. Legacy fields Modern complex attributes Legacy to modern transfer
  • When a product has SKU rows, map each SKU row to one Shopify variant under the product's handle, and leave the Product row's SKU out of the variant list. A product with no SKU rows is one variant and keeps the Product row's SKU. Why it bites: with SKU rows present, the parent SKU is the product and each SKU row is a variant, which BigCommerce calls "SKU for variants." "Do not use commas in SKUs," a SKU is case-insensitive with a maximum of 255 characters, and Product ID is "The system-generated product identifier." Legacy fields
  • Read the option text on the SKU row's Product Name. Why it bites: a size option is written [RB]Size=Small. Two options on one variant are separated by a comma with no space before or after, as in the note above, for example [RB]Size=Small,[CS]Color=Blue:#0000FF. On an existing SKU row, Product Name is read-only, and changing an option name creates a new option. Complex attributes Updating products
  • Take the variant price from the SKU row's Price, then read the Rule row before you drop it. Why it bites: "Variant weight and price are displayed in the SKU row, but must be updated in the Rule row." A rule price is [ADD]#, [REMOVE]#, or [FIXED]#, for example [FIXED]25 or [ADD]25%, so a tag is not a Shopify Price. Updating an existing rule requires the ID, so check in your own export. Updating products Complex attributes
  • Do not write Sale Price or Retail Price onto a variant from a legacy import column. Why it bites: "Sale price cannot be assigned to variants via import" and "MSRP cannot be assigned to variants via import." "if entered, it will replace the base price" is what Sale Price does on the product, and "if entered, it will appear next to your base or sale price" is what Retail Price does. When you are creating options, "Adding sale or retail (MSRP) pricing" is not supported, and the rest of the disagreement is in the note above. Legacy fields First import
  • Read Sale Price and Retail Price before you copy either number. Why it bites: "When Sale Price is set on a product, that value will override the Default Price on the storefront." "Adding a MSRP (Retail Price) will show it with a strikethrough, and will display the difference (amount saved) between the retail price and regular price (or Sale Price if entered)." Sale pricing
  • Put the amount the customer pays in Shopify Price. Put Retail Price in Compare-at price only when you want that struck-through display. Why it bites: "Make sure that the value in the Compare-at price field is higher than the value in the Price field to display the sale price." "only the sale price is displayed at checkout." Filling Compare-at from Retail Price can make the theme show a sale even when Sale Price is empty, because the theme controls whether and where a sale is shown. Shopify sale prices
  • Leave a blank price blank until you know which of the three statements applies. Why it bites: a blank becoming 0 is what BigCommerce documents for creating a new product, and a blank that means the same price as the base product is the modern create-a-variant case and, separately, the custom transfer template. The Shopify Price column says "The default value is 0.00 if no value is entered," which is the column, not a BigCommerce rule. The three statements are in the note above. That setting is not the create-a-product rule that a blank price becomes 0. Updating products Modern overview

The legacy overview says you can "add or edit price and weight rules for existing modifier options," but the transfer page says "product modifier options cannot be imported or exported in either experience," and Rule rows with no SKU "cannot be imported using the modern Import/Export tool."   • Do not look for bulk pricing in the product CSV. Why it bites: "If a field is not in the list below (such as bulk pricing), it cannot be imported, exported, or created manually in the CSV file." Legacy fields Bulk pricing
  • Use the Price List Importer/Exporter app to bulk edit existing price lists or create new ones, not the product CSV. Why it bites: "Price lists let you offer advanced variant-level price overrides based on storefronts and customer groups." "any customer group-storefront combination can only be assigned to a single price list at a time," and "You cannot use both customer group discounts and a price list at the same time for a customer group." Price lists need a Performance plan, and the storefront cannot use a Blueprint theme. Price lists
  • Read a missing price-list row as catalog price, not as a zero. Why it bites: "If an active Price List does not contain prices for a variant, the catalog pricing will be used," and on a multi-currency store a missing price falls back to the catalog price "or in the case of multi-currency, auto-converted prices." "If a variant has a Price Record, any existing product-level bulk pricing will not apply to the cart." "For variants without Price Records, any existing product bulk pricing will apply." Price list API
  • Keep price lists, customer groups, and quantity breaks out of Shopify Price. Why it bites: the main columns are Price and Compare-at price. Some markets also add Price / [Market] and Compare At Price / [Market], which are not BigCommerce price lists, and a market has those columns only if "exactly one of its active catalogs isn't shared with another market." Product CSV columns
  • Decide which storefront is the Shopify store before you copy a name or a price. Why it bites: "Storefronts share your store’s catalog. You can choose which products appear on which storefronts." "product attributes (like description and name) cannot be overridden into a different language without customization," and you can "Use Price Lists for custom pricing on each storefront" and "Control product purchasability per storefront." Multi-storefront
  • Read the modern Channels cell as storefront ids, and do not expect that cell on Shopify. Why it bites: "Your default storefront will always have a channel ID of 1," and further ids are separated by a semicolon. Shopify's product CSV has no storefront column. Published on online store is the online store channel, and "CSV files can't be used to bulk update product availability on other sales channels." Modern fields Product CSV columns
  • Map Product Visible? separately from Allow Purchases?, and do not read Product Availability as a status. Why it bites: Product Visible? uses Y to be visible and N to "disable product visibility," while Allow Purchases? uses Y to allow purchase or pre-order and N when the product "cannot be purchased or pre-ordered." Product Availability is "A brief description of how long it takes for your product to ship." Product Not Visible is read-only, so use Product Visible?. Legacy fields

If the Status column is absent, "the product status is automatically uploaded as active." The admin also has Unlisted, "accessible only by its URL," and that word is not in this CSV value list. Customers and orders

  • Import products first, then customers, then historical orders. Why it bites: orders need products and customers already in the store if those records are to connect. Migrate to Shopify
  • Export customers from Customers › Export, not from the product file. Why it bites: Default "Includes only basic customer details, such as first name, last name, email address, phone number, and addresses," and Bulk Edit "Includes the majority of exportable fields." A BigCommerce customer import requires Email Address, First Name, and Last Name, and is capped at 2 MB ("Customer import files must be 2 MB or less"), which matters only if you import a file back into BigCommerce. Shopify's limit is in the Shopify import item below. Customer import and export
  • Do not expect a password in the customer export. Why it bites: "passwords cannot be exported via CSV file, however they can be imported" into BigCommerce, and the Orders count is "exportable only" and not in the Bulk Edit template by default. Customer import and export
  • Use Shopify's province and country codes, not BigCommerce's spelled-out state. Why it bites: if you edit the file and import it back into BigCommerce, changing the email column "will create a new customer record" and the state "must be spelled out, not abbreviated." Those are BigCommerce rules. Shopify's customer CSV uses Default Address Province Code and Default Address Country Code, an ISO code and an ISO Alpha-2 code. Customer import and export Importing customers
  • Import Shopify customers with the customer CSV, and plan a new password. Why it bites: "You can only import customer CSV files that are 15 MB or smaller." The Email column is required, and the value can be blank, and Total Spent and Total Orders "aren't imported." "you need to invite your customers to create new passwords," and with sign-in links customers receive a one-time 6-digit code and "A password isn't required to sign in." Content

  • Copy pages across, or move them with an app or the Page API. Why it bites: the product export is not a page export, and the migration guide does not offer a page CSV. Migrate to Shopify
  • Copy blog posts into a Shopify blog, or move them with an app or the Blog API. Why it bites: posts are not in the product CSV, and Shopify's migration guide lists blogs under migration apps, the Blog API, and the Blog Article API. On Multi-Storefront, "some store functions are global and are shared across storefronts, such as the built-in blog," so the posts are one set for every storefront. Multi-storefront Migrate to Shopify
  • Plan reviews on their own. Why it bites: the legacy field list has no reviews column, and a field that is not in it "cannot be imported, exported, or created manually in the CSV file." The transfer page also lists product reviews among the attributes the modern BigCommerce tool cannot import. Check in your own export for where reviews live before you assume they arrived with the catalog. Legacy fields Legacy to modern transfer

SEO

  • Export BigCommerce redirects from Settings › 301 Redirect, using Export All, for one storefront or for all of them. Why it bites: the redirect CSV import file has five columns, Domain, Old Path, Manual URL/Path, Dynamic Target Type, and Dynamic Target ID, and the export option "Export dynamic redirect URLs" adds Dynamic Target URL (read-only). Dynamic Target Type can be Product, Brand, Category, Page, or Blog Post, and Manual URL/Path "will be blank" for a dynamic redirect. "301 redirects are automatically created whenever the name or the URL of a product, category, or webpage is changed." 301 redirects
  • Set Redirect Old URL? only when you still need that redirect inside BigCommerce. Why it bites: "Type in Y to create a 301 redirect, or N to not create a redirect from the old product URL." A redirect created there stays in BigCommerce. The old path you still need on Shopify is a separate redirect. Legacy fields
  • Add a Shopify URL redirect for every old path you still need. Why it bites: "You can redirect only from broken URLs," and if the URL still loads a valid webpage, "the URL redirect won't work." You cannot redirect fixed paths such as /products, /collections, or /collections/all, or a path that begins with /apps, /application, /cart, /carts, /orders, /services, or /shop. The page also reserves /collections/vendors, /collections/types, /a/, /community/, and /tools/, and MyShopify domain paths ending in /shop or /services, and a store can store 100,000 URL redirects, or 20,000,000 on the Plus plan. URL redirects
  • Do not point a .html URL at the same path with .html removed. Why it bites: "URLs ending in .html cannot be redirected to the same URL without .html. Shopify treats these as the same URL." Query strings "might not work as expected," and BigCommerce's own reserved list (/index.php, /admin, /manage, /graphql, plus more on a Blueprint theme) limits redirects made inside BigCommerce, while Shopify's list is in the previous item. URL redirects 301 redirects
  • Read the new path from the live Shopify page before you write the redirect. Why it bites: BigCommerce describes Product URL as "The relative path of your product's URL on your store," and the Shopify page says only that the URL handle "is used in the URL of the product page," so read the full path from the live page. Product CSV columns Legacy fields
  • After you remove a redirect, request the old URL again. Why it bites: "301 redirects are cached by browsers and search engines. If you remove a redirect after customers have accessed it, then the redirect might continue to work in their browsers until the cache expires." URL redirects

Launch day

  • Spot-check one product with SKU rows, one product with no SKU rows, one Rule row whose price is [FIXED], one product whose Sale Price is empty and whose Retail Price is filled, and one product with Product Visible? N. Why it bites: Shopify's migration guide lists "Product variants failed to import" and products imported but not published as common problems.   • Place a test order, then cancel or refund it. Why it bites: checkout, tax, shipping, and the notification emails are not proven by a CSV.
